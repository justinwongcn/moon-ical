02标准功能轴：用什么尺子量深浅

iCalendar 不是一份规范，而是十几份叠在一起的规范。做功能对照必须先固定尺子，否则各家 README 各说各话。

2.1 规范清单

规范管什么本轮核实到的状态
RFC 2445旧版 iCalendar已被 5545 取代；库不再声称支持，但历史数据仍会遇到
RFC 5545核心对象：组件、属性、值类型、RRULE、VTIMEZONE现行 standards track；所有被调研库的第一主张
RFC 5546iTIP 调度语义（PUBLISH / REQUEST / REPLY / ADD / CANCEL / REFRESH / COUNTER）组织者—出席者模型与 PARTSTAT 所在；两语言实现都稀薄
RFC 6047iMIP：用邮件承载 iTIPGo 的 floatpane/go-icalendar 明确以它为目标
RFC 6321xCal（XML 表示）icalendar 明确不声称兼容（其 issue #1135）
RFC 6350 / 6352vCard 4.0 / CardDAV联系人侧；icalendar 不声称支持 vCard
RFC 6578WebDAV 集合同步（sync-token 增量）同步器命脉；Radicale 与多个 Go 客户端/服务端实现
RFC 6868参数值编码（引号与 ^ 转义）最容易做错的一处；icalendar 与 ical 均列为支持
RFC 7529RSCALE 非格里高利历递归icalendar 列为支持；recurring-ical-events 列为 TODO
RFC 7953VAVAILABILITY 可用性icalendar 列为支持；recurring-ical-events 列为 TODO
RFC 7986新增属性（TITLE / DESCRIPTION / COLOR / IMAGE / CONCEPT / REFID…）icalendar、ical 支持；前者有专门的 COLOR 实现
RFC 8536TZif 时区数据格式Python ical 列为支持，其时区指南围绕它展开
RFC 9073 / 9253事件关系（RELATED-TO / DERIVED-FROM-UID）icalendar 称 9073"可能部分可用"（issue #656），并列 9253 为支持
RFC 9074VALARM 扩展icalendar 列为支持
RFC 4791 / 4918CalDAV / WebDAV协议层；Go 侧由 emersion/go-webdav、codanael/caldav-go 覆盖
RFC 8984JSCalendar（JSON 表示）不在本轮范围，但与 §2.2 动向直接相关

2.2 标准组织的当前动向（影响"现在补哪层更保值"）

IETF calext 工作组同时维护 iCalendar / iTIP / iMIP / CalDAV / CardDAV / JSCalendar 整套规范。 本轮取到的工作组页面显示：2026-07-20 里程碑"Adopt an RFC9555bis document"已标记为 Done； draft-ietf-calext-icalendar-jscalendar-extensions（v05，2026-01-19）截至本轮 处于 In WG Last Call，对应里程碑到期日 2026-08；另有 draft-kashyap-calext-ical-property-deps-00（2026-03-30）在给 iCalendar 属性依赖做机器可读化。 含义：核心仍是 RFC 5545，短期不会推倒重来；但iCalendar 与 JSON 表示之间的映射正在标准化—— 把数据模型与文本编解码干净分离的实现，将来接入成本最低。

2.3 RRULE 词汇表：衡量展开器的刻度

递归展开最能拉开实现差距，刻度就是这份 PART 清单。下表取自 Go 侧 floatpane/go-icalendar README 自带的 "Supported RRULE parts" 表（官方声明）—— 它是本轮见到的唯一一份逐 PART 自报家门的表，故用它当基准刻度。

PART作用该实现自报状态
FREQSECONDLY … YEARLY 粒度✓ 支持
INTERVAL步长✓ 支持
COUNT / UNTIL终止条件（二者互斥）✓ 支持
BYMONTH限月✓ 支持
BYMONTHDAY限月内日（含负数，-1 = 月末）✓ 支持
BYDAY限星期，含序数前缀（2MO / -1FR）✓ 支持
BYSETPOS候选集合取第 N 个（"每月最后一个周五"）✓ 支持
WKST每周起始日✓ 支持
BYWEEKNO限 ISO 周序± 解析但展开时忽略
BYYEARDAY限年内日± 解析但展开时忽略
RDATE / EXDATE额外加入 / 剔除具体实例✓ 合并处理
RECURRENCE-ID单实例改期 / 取消（同 UID 多 VEVENT）± 需调用方自建覆盖表
EXRULE排除整条规则✗ 规范中已废弃，普遍不做
RSCALE / SKIP非格里高利历递归（RFC 7529）✗ 仅 icalendar 声称支持
「解析但忽略」是这一层最危险的档位。 BYWEEKNO / BYYEARDAY 静默失效，产出的是一张"看起来合理、但少了几十个实例"的日程表， 用户无从察觉。若 moon-ical 暂不支持某个 PART，宁可显式报错或降级警告，也不要照抄静默忽略。
