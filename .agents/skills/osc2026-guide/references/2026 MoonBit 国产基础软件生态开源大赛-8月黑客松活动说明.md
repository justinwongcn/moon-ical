# 2026 MoonBit 国产基础软件生态开源大赛-8月黑客松活动说明

来源：[飞书活动说明](https://bxup9uklfcb.feishu.cn/wiki/KNrVwEVFziPHiGkQtwhc6w3gndd)

2026 MoonBit 国产基础软件生态开源大赛比赛初审结束后，我们收到了许多同学的反馈：有的同学因为没能及时参与而感到遗憾，也有同学在询问下一次比赛的举办时间。

为此，团队决定延续“2026 MoonBit 国产基础软件生态开源大赛”，举办 8 月黑客松活动，并将本次 8 月黑客松活动的报名截止时间延长至 2026 年 8 月 24 日 24:00。

## 一、活动定位

本次活动以 MoonBit 编程语言及其工具链为基础，面向全体开发者，鼓励参赛者借助 AI 工具，完成开源生态库、开发工具和示例工程的设计、开发、移植与完善。

学生、社会人士，以及其他对 MoonBit、AI 编程、开源生态和基础软件感兴趣的开发者均可报名参加。

## 二、报名安排

- 报名时间：2026 年 7 月 22 日至 8 月 24 日
- 报名截止：**2026 年 8 月 24 日 24:00**
- 报名方式：填写[飞书报名问卷](https://bxup9uklfcb.feishu.cn/share/base/form/shrcnfItHeB1viw56y3cGNGMqub)，也可以扫描活动说明中的二维码填写问卷。

奖励：

- 通过初审：获得 150 元/人
- 通过项目验收：再获得 350 元/人
- 完整通过初审和验收：合计获得 500 元/人

## 三、报名及项目申报材料

报名时需要准备：

- 参赛者基本信息
- 公开且可以正常访问的在线代码仓库链接
- 一页左右的 Markdown 项目申报书
- 项目现有基础说明
- 本次计划开发或新增的内容
- 项目预期目标和技术路线
- 预计完成的功能、测试和文档
- 移植项目还需说明原项目、原项目链接、许可证及本次移植范围

项目申报及材料提交以本次 8 月黑客松飞书问卷和后续官方通知为准。

## 四、项目类型与基本要求

参赛项目可以是：

- 原创 MoonBit 开源库
- 将其他语言生态中的成熟开源库移植到 MoonBit
- 围绕实际开发需求制作的开发工具
- 使用 MoonBit 实现的示例工程

项目应尽量避免与 MoonBit 生态中已经存在、功能高度重合的成熟项目重复。

项目应以 MoonBit 作为主要实现语言，可以包含必要的绑定代码、配置文件、构建脚本及其他辅助内容，但核心功能应主要使用 MoonBit 实现。

## 五、项目规模

项目参考规模为 4,000 至 10,000 行有效 MoonBit 代码。

代码行数不是强制验收标准，项目验收更看重：

- 项目是否真实可用
- 项目功能和适用边界是否清晰
- 工程结构是否合理
- 文档是否清楚、完整
- 测试是否能够正常运行
- 示例是否能够实际执行
- 项目是否便于长期维护
- 项目是否对 MoonBit 生态具有实际价值

## 六、代码仓库及验收要求

参加验收的项目应满足以下条件：

- 以 MoonBit 作为主要实现语言
- 代码仓库公开且可以正常访问
- 提供清晰、完整的 README
- 说明项目用途、主要功能及使用方法
- 提供可以实际运行的示例
- 配置持续集成（CI）
- 提供可运行的测试
- 项目能够正常构建
- 按要求发布至 mooncakes.io
- 开发过程和提交记录可以追踪
- 项目具有明确的功能边界和后续维护价值
- 使用的第三方代码、素材和依赖符合开源许可证要求

开发过程中建议保留：

- Git 提交记录
- Issue 或工单记录
- 合并请求记录
- 测试记录
- 更新日志
- 版本发布记录
- 重要技术方案和设计说明

## 七、移植项目要求

允许将其他语言生态中的成熟开源库移植到 MoonBit，包括但不限于：

- Rust
- Go
- TypeScript
- Python
- OCaml
- Scala
- Java

移植项目必须注明：

- 原项目名称
- 原项目链接
- 原项目采用的开源许可证
- 本次移植的具体范围
- 对原项目所做的修改和适配
- 尚未移植或暂不支持的功能

不得将他人的现有成果直接作为原创项目提交。

## 八、开源与版权要求

参赛项目必须采用 OSI 认可的开源许可证。

不得提交：

- 未经授权的私有代码
- 闭源代码
- 商业代码
- 来源不明的代码或生成内容
- 违反原项目许可证要求的移植代码
- 侵犯第三方知识产权的内容

如果使用、参考或移植其他开源项目，应保留必要的版权、许可证和来源说明。

参赛者需要自行确认所使用代码、依赖、文档、图片及其他素材的授权情况，并对项目的开源合规性负责。

## 九、AI 工具使用规则

活动允许合理使用 AI 工具辅助开发，包括：

- 代码生成
- 接口设计
- 测试补全
- 文档撰写
- 项目移植分析
- 代码解释
- 调试和工程改进

参赛者需要对以下内容负责：

- 项目目标
- 技术路线
- 代码质量
- 功能边界
- 项目安全性
- AI 生成内容的来源和准确性
- 第三方代码及开源许可证合规
- 最终成果的可解释性
- 项目的可测试性和可维护性

不得借助 AI 工具提交未经授权的私有代码、闭源代码、商业代码或来源不明的内容。

## 十、参考项目方向

- Python、Lua、Visual Basic 等语言的解释器/运行时
- 事件总线与消息抽象层
- QUIC 协议库
- 前端状态管理与表单校验库
- API 动态规则校验引擎
- 轻量 WebHook 处理框架
- MoonBit 原生的 WAV / OGG 音频解码库
- 确定性分布式系统仿真框架
- LaTeX、Typst 等排版语言的渲染库
- LSP 语言服务器框架
- 类似 OGDF、d3-force 的自动布局引擎
- 经典命令行工具 find、cat、ls 等的现代替代
- HTTP Web 服务器、反向代理服务器
- 类似 Spark、Flink 的大数据处理引擎
- 分布式 SQL 查询引擎
- Actor 模型并发框架
- 基于 Wasm 的 Kubernetes Operator 运行时
- OCI 镜像打包工具
- 类似 ReactiveMongo 的响应式数据库驱动
- 其他具有展示性和复用价值的应用项目

以上方向仅供参考，参赛者也可以根据实际需求选择其他具有生态价值的项目。

## 十一、奖励说明

- 通过初审：获得 150 元/人
- 通过项目验收：再获得 350 元/人
- 完整通过初审和验收：合计获得 500 元/人

## 十二、推荐奖励

成功报名的参赛者可以邀请新参赛者参加活动。

推荐奖励规则如下：

- 每成功推荐 1 名新参赛者，可获得 50 元奖励
- 每位推荐人最多奖励 30 人
- 被推荐人需在报名问卷的“推荐人”字段中准确填写推荐人的手机号码
- 一名被推荐人只能绑定一名推荐人
- 若被推荐人收到多人邀请，以报名问卷中首次有效提交的推荐人信息为准
- 推荐关系经活动团队审核确认后不能修改
- 推荐人与被推荐人不得相互推荐
- 不得重复推荐或使用虚假账号获取奖励
- 发现违规推荐行为后，活动团队有权取消相关人员的参赛资格和奖励

## 十三、审核及反馈

提交飞书报名问卷和项目申报材料后，活动团队将通过邮件等方式通知审核结果。

- 通过初审的项目可以获得 150 元启动支持，并进入项目开发和验收流程
- 未通过初审时，活动团队将反馈相关原因
- 参赛者可以根据反馈调整项目内容后重新提交

报名时请填写常用且可以正常接收通知的邮箱和联系方式，并及时查看邮件及相关活动通知。
